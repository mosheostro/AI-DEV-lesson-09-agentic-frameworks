# Security and MFA Policy

Owner: IT Security
Effective date: 2026-06-01

## Precedence

This policy overrides general access guidance wherever the two conflict — security
requirements are not negotiable for convenience, regardless of what the Access
Management Policy allows in general.

## Authentication

All accounts use MFA through Okta, with no exceptions for seniority or tenure. New
devices require identity verification before they can access company systems, even
for an employee who has already completed MFA setup on a different device.

## Contractor access

Contractors may not receive persistent admin access on any system, under any
circumstance. Contractor GitHub access specifically requires all of the following
together: named repository scope (not org-wide access), manager approval, IT
approval, a defined end date, and MDM compliance on the device being used. Missing
any one of these blocks the grant.

## Incident reporting

Employees and contractors must report suspected security incidents — a phishing
email that was clicked, a lost device, unexpected account activity — to IT Security
immediately, not after trying to fix it themselves first. Early reporting is what
keeps a small incident small; a self-remediated incident often destroys the
evidence Security needs to assess what actually happened.
